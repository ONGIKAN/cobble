## 2. 产品定义

### 2.1 目标用户

- **主用户 A：青少年/学生创作者**（10–18 岁，教育场景与自学），通过积木低门槛做出可玩的 2D 小游戏。
- **主用户 B：轻量业余创作者**，想要"比写代码快、比 Scratch 自由"的小游戏制作工具。
- **次用户：教师/家长**（后续版本再服务），需要示例、模板与作品分享。

### 2.2 核心用户旅程（MVP 必须走通）

```
打开示例模板/空白工程
  → 在舞台拖入角色、设置大小位置
  → 从积木面板拖出积木、拼装逻辑（当绿旗点击 → 移动 → 碰到金币 → 加分）
  → 点"运行"在舞台预览（所见即所得）
  → 自动保存到本地工程列表
  → 导出 .gproj（可再导入编辑）
  → [P1] 导出单文件 HTML5 → 发给朋友双击即玩
  → [P3] 发布到平台 → 分享链接，别人浏览器打开就玩
```

### 2.3 MVP 范围（P0–P1）

**做：**
- 单舞台、多角色、帧动画造型（不做矢量绘制）
- 42 个积木块 + 预制示例
- 舞台预览运行（同一套运行时）
- 工程自动保存、工程列表、`.gproj` 导出/导入
- 内置素材库（P1）+ 用户上传 PNG/MP3（P1）
- 单文件 HTML5 导出（P1）
- 中英双语界面（i18n 基建从第一天做，语言可切换）

**明确不做（砍掉的理由：一个人+AI 的产能边界）：**
- 多人联机、3D、物理刚体（只用简单 AABB 碰撞/距离判定）
- 自研渲染引擎（直接用 Phaser）
- 移动端编辑器（先只做桌面/Web；手机端 P-later 只做"游玩端"）
- 微信/抖音小游戏导出（渠道适配后置）
- AI 生成内容、账号、社区、付费（P3 之后）
- 视频/多场景转场/粒子编辑器/音效合成

### 2.4 MVP 验收标准

1. 一个新用户不看文档，**30 分钟内**做出一个能玩的小游戏。
2. 关掉浏览器再打开，工程原样恢复；导出 `.gproj` 在另一台机器导入后能继续编辑并运行。
3. 导出的 HTML5 文件**双击可玩**（file:// 下正常运行）。
4. 编辑器中预览行为与导出运行时**完全一致**（同一份 runtime 代码）。

## 4. 核心设计

### 4.1 工程数据模型

`project.json` 结构（`.gproj` = 这个 JSON + `assets/` 目录打成 zip）：

```jsonc
{
  "schemaVersion": 1,
  "meta": { "id": "uuid", "name": "我的第一个游戏", "createdAt": "...", "updatedAt": "..." },
  "stage": { "width": 960, "height": 540, "background": { "type": "color", "value": "#87CEEB" } },
  "assets": [
    { "id": "asset_cat", "type": "image", "name": "小猫.png", "path": "assets/asset_cat.png",
      "hash": "sha256:...", "size": 12345 }
  ],
  "variables": [ { "id": "var_score", "name": "分数", "value": 0 } ],
  "sprites": [
    {
      "id": "sprite_cat", "name": "小猫",
      "x": 0, "y": 0, "rotation": 0, "size": 100, "visible": true, "zIndex": 1,
      "rotationStyle": "left-right",
      "costumes": [ { "name": "造型1", "assetId": "asset_cat" } ],
      "sounds": [],
      "scripts": { "workspace": { /* Blockly serialization JSON */ } }
    }
  ]
}
```

规则：
- **所有 ID 稳定不改名**，积木引用角色/变量/素材一律用 ID，不用显示名。
- **工程文件不含界面文案**：i18n 资源在代码侧；`.gproj` 只存用户内容与稳定 ID，换语言打开同一工程行为与内容一致。
- `schemaVersion` 从第一版就加，迁移函数注册表 `migrations[from→to]`，保证老工程能打开。
- 资产存路径 + hash，导入时校验，缺失资源给出占位并警告。
- Blockly workspace JSON 直接内嵌（Blockly 官方序列化格式），不做二次发明。

### 4.2 积木语言设计（MVP）

- 42 个积木块，见**附录 A**（分类/名称/参数/IR 指令）。
- 设计原则：
  1. **面向 8–14 岁可读**：中文、大色块、口语化命名（"当绿旗被点击"而非 "onStart"）。
  2. **语义可执行**：每个块都直接映射到一条 IR 指令，不引入虚拟机级复杂度。
  3. **可扩展**：积木定义 = `{ blockJson, toolboxEntry, compile(block, ctx) => IRNode[], codegen(block, ctx) => string }` 注册表，加块只加文件、不改核心。
  4. **双视图（差异化卖点）**：Blockly 自带 JS generator → 右侧"代码视图"只读展示生成的 JS；P1 起可导出 JS 源码用于教学。**MVP 不做 JS→积木反向解析**。
  5. 碰撞判定用**侦测轮询**（"碰到 X？"）而不是碰撞事件 hat，大幅降低调度器复杂度。

- 参考：Scratch 3 的块分类与命名、Blockly 官方 demo 的触屏案例。

### 4.3 编译器：Blockly 工作区 → IR

```
Blockly workspace JSON
  → 遍历顶层 hat 块
  → 每个 hat 生成一个 Script 单元
  → 语句块 → IRNode[]，表达式块 → IRExpr
  → 变量/角色/素材引用解析成 ID 与槽位
  → 输出 IR（纯 JSON，可测试、可序列化）
```

IR 示例（`当绿旗被点击 → 重复 10 次 [移动 10 步；如果 碰到金币 那么 分数+1]`）：

```jsonc
{
  "scripts": [
    {
      "hat": { "type": "onFlag" },
      "body": [
        { "op": "repeat", "times": { "kind": "const", "value": 10 }, "body": [
          { "op": "move", "steps": { "kind": "const", "value": 10 } },
          { "op": "if", "cond": { "kind": "touching", "target": { "kind": "sprite", "id": "sprite_coin" } },
            "then": [ { "op": "changeVar", "varId": "var_score", "delta": { "kind": "const", "value": 1 } } ] }
        ] }
      ]
    }
  ]
}
```

编译器的价值：**IR 是唯一执行真相**，编辑器预览和导出包跑的都是它，天然保证"预览=导出"。

### 4.4 运行时：执行模型与调度器（本项目最核心、最容易写错的部分）

执行语义（对齐 Scratch 的精神，但不做完整 fiber）：

- 每个 hat 块 = 一个 **thread（脚本实例）**；条件满足时创建，跑完销毁。
- 每个角色/舞台各自持有一组 thread；每帧（60fps）调度器遍历所有 thread 执行。
- **yield 规则**：
  - `等待 n 秒`：挂起到时间到；
  - `重复 n 次` / `一直重复`：每完成一次迭代 yield 一帧（与 Scratch 一致，循环不会一帧跑完）；
  - 运动类瞬时块：同帧连续执行；
  - `滑行到`：注册 tween，期间 yield。
- **防死锁预算**：每帧给每个 thread 最多 `2,000` 条指令，超出强制 yield 到下一帧（防止 `一直重复 [什么都不做]` 卡死浏览器）。
- 事件（MVP 4 种）：绿旗、按键按下、角色被点击、收到广播消息。
- 顺序：每帧先处理输入/物理引擎，再跑调度器，最后渲染（由 Phaser `update` 驱动）。
- 状态：所有 thread 的栈保持在运行时内存，工程加载后从"绿旗"重新开始（MVP 不做运行中存档）。

**单元测试必须覆盖**：循环 yield 次数、等待时长误差、指令预算、广播、停止脚本、变量作用域。

### 4.5 引擎适配层（`packages/engine-phaser`）

```ts
interface EngineAdapter {
  // 生命周期
  init(container: HTMLElement, project: LoadedProject): Promise<void>;
  destroy(): void;
  onFrame(cb: (dtMs: number) => void): void;
  // 角色
  ensureSprite(spriteId: string, def: SpriteInit): void;
  setTransform(spriteId: string, t: { x: number; y: number; rotation: number; scale: number }): void;
  setVisible(spriteId: string, visible: boolean): void;
  setZIndex(spriteId: string, z: number): void;
  setCostume(spriteId: string, index: number): void;
  tweenTo(spriteId: string, t: TargetTransform, seconds: number, onDone: () => void): void;
  getBounds(spriteId: string): Bounds;
  // 舞台 / 输入 / 声音
  stageSize(): { width: number; height: number };
  isKeyDown(key: string): boolean;
  isMouseDown(): boolean;
  mousePosition(): { x: number; y: number };
  touchTargets(): { x: number; y: number }[];   // 角色被点击检测
  playSound(assetId: string): Promise<void>;
  stopAllSounds(): void;
  setVolume(v: number): void;
}
```

- 编辑器与运行时只依赖这个接口；Phaser 4 是唯一实现。
- 再提供一个 **HeadlessAdapter**（纯数据模拟），让调度器/编译器单测不依赖 WebGL。
- 切换 PixiJS 的触发条件（写进 ADR）：Phaser 包体积或渲染性能成为瓶颈、或需要完全自定义渲染时。

### 4.6 沙箱与安全

- 预览与导出都跑在 **iframe** 中：`<iframe sandbox="allow-scripts">`（不加 `allow-same-origin`），与编辑器通过 `postMessage` 通信。
- 通信协议：
  - 编辑器 → 播放器：`{ type: "load", project: CompiledProject, assets: Blob[] }`；
  - 播放器 → 编辑器：`ready` / `error` / `running` / `stopped` / `fps`。
  - 资产用 Blob/ArrayBuffer 结构化克隆传递，避免跨域 fetch。
- 积木是 **IR 解释执行，不生成也不执行用户 JS**，MVP 天然没有代码注入面；P1 若做"导出 JS"，导出代码只在用户本地/导出包中，不在编辑器内执行。
- 后续 UGC 上线时补：上传内容审核、举报、CSP、未成年人保护（不收集未成年人个人信息）。

### 4.7 导出与导入

| 产物 | 内容 | 用法 |
|---|---|---|
| `.gproj` | zip：`project.json` + `assets/*` | 存档、分享工程、导入继续编辑 |
| `game.html`（单文件） | 内联 player bundle（IIFE）+ 内联 project JSON + assets 转 data URI | **双击即玩**，发给朋友、上传网盘/itch.io |
| 目录版（P2） | `index.html` + `runtime.js` + `project.json` + `assets/` | 更大工程用，需本地/静态服务器托管 |

关键实现细节：
- 单文件用 **IIFE + 内联**，不要 ES module（避免 `file://` 下的 CORS/模块加载失败）。
- 单文件体积上限建议 30MB（素材多时提示改用目录版或压缩素材）。
- 导入 `.gproj` 必须先过 zod 校验 + 版本迁移，损坏文件给出可读错误。

### 4.8 本地存储与自动保存

- 工程列表（IndexedDB/Dexie）：`projects` 表存 project.json，`assets` 表存 Blob。
- 自动保存：编辑变更 debounce 2s 落 IndexedDB；首屏显示"最近工程"。
- 桌面端（P2）：Tauri `fs` 插件做真正的文件打开/另存为，`.gproj` 文件关联双击打开。
- 崩溃恢复：运行中的未保存变更写 `draft` 键，下次打开提示恢复。

### 4.9 桌面客户端（P2）

| 项 | 选择 | 说明 |
|---|---|---|
| 壳 | Tauri 2 | 安装包 ~10MB vs Electron ~150MB |
| 渲染 | 系统 WebView（Win: WebView2 / macOS: WKWebView / Linux: WebKitGTK） | 占用小、启动快 |
| 能力 | 本地文件对话框、`.gproj` 文件关联、系统菜单、自动更新（updater 插件） | — |
| 构建 | GitHub Actions 三平台矩阵 | macOS 构建需 macOS runner（注意免费额度倍率） |
| 何时换 Electron | 若 Linux WebKitGTK 的 WebGL 性能/兼容性验证失败，或需一致渲染 | 第 1 周 POC 决定 |

### 4.10 多端策略

- **P0–P2：桌面/Web 优先**（编辑器体验需要大屏 + 键鼠）。
- **P3 后：移动端只做"游玩端"**（Player + Capacitor 套壳），编辑器移动版不做。
- 平板编辑器（触摸积木拖拽）列为"验证后可选"，不在 MVP 承诺范围。

### 4.11 平台化（P3）：在线发布 / 账号 / 社区

- **在线发布 = 纯静态托管**：作品导出 HTML5 + 工程 JSON，上传到 **Cloudflare R2（0 egress 费）+ Cloudflare Pages** 或 GitHub Pages；分享链接直接打开。
- **账号/社区**：Supabase（Auth + Postgres + Storage 免费层）优先，比自建后端省 2–3 周；数据量上来再迁。
- 成本预期：早期几百个作品 → **$0–15/月**；真正花钱的是图片/音频流量，做 CDN 缓存与素材压缩即可。
- 分享页功能：作品播放 + 作者 + 点赞/评论 + remix（复制工程到自己的账号，需 block 编辑权限）。
- 社区是护城河但也是最大成本项，**必须排在"作品导出/分享链接"之后**。

### 4.12 多语言（i18n）设计（P0 就做）

> 原则：**语言从第一天就是架构的一部分，不是做完再翻译一遍。**（用户要求，m00064）

#### 两层语言模型（最关键的一条）

| 层 | 内容 | 存哪 | 谁负责 |
|---|---|---|---|
| 界面语言 UI | 编辑器按钮/菜单/提示、**积木块文字**、模板与素材的展示名/描述、错误信息 | 代码内资源包 `packages/i18n/locales/{zh-CN,en}/*.json` | 开发者维护（中英首发） |
| 作品内容语言 | 用户游戏里自己写的文字（"说 你好"、造型名、对话台词）、示例工程内容 | 工程文件 `.gproj`（用户数据） | 不自动翻译，用户自己写 |

- **`project.json` 与 IR 里只存 ID 和用户内容，绝不存界面文案**——工程文件与语言无关，换语言打开行为一致。
- 内置示例模板的**展示名/描述**走 i18n key；模板里给玩家看的台词属于作品内容，P1 起各语言模板可各带一份。

#### 技术实现

1. **i18next + react-i18next**（生态最大、AI 语料最多）；复数/日期/数字用 `Intl` API。
2. 资源按命名空间拆分：`common / editor / blocks / templates / errors`，路径 `packages/i18n/locales/{zh-CN,en}/<ns>.json`。
3. **类型安全 key**：由 zh-CN 资源生成 `i18next.d.ts` 的 key 联合类型，写错 key 编译期报错。
4. **CI 完整性校验**：脚本比对各语言 key 集合，缺 key / 多 key 直接失败；开发环境缺 key 打 `console.warn` 并回退 zh-CN，不崩溃。
5. 语言检测与持久化：`localStorage['app.locale']`，默认 `navigator.language`，回退 zh-CN；桌面端存 Tauri store。
6. **积木块文案**：块定义里用 message key（如 `blocks.motion.move_steps.message0`），不硬编码中文；Blockly 内置文案（右键菜单、变量对话框、工具箱搜索）通过覆盖 `Blockly.Msg` 翻译。
7. **Blockly 切换语言**：Blockly 的块定义在注册时即求值文案，切换语言必须重新注册 + 重建工作区。MVP 采用最稳方案：**切换语言 → 先保存（自动保存即可）→ 重载页面**；写进 ADR，不为它魔改 Blockly。桌面端与 Web 端同样处理。
8. **RTL 预留**：语言元数据带 `dir: ltr|rtl`，CSS 只用逻辑属性（`margin-inline-start`、`inset-inline`），将来加阿拉伯语不返工。
9. 文案规范：key 命名 `模块.组件.用途`；用户可见字符串禁止硬编码（code review + 可选 ESLint 扫描）；开发日志可英文，**用户可见错误必须 i18n**。

#### 明确不做

- 作品内容自动翻译 / AI 翻译（未来独立功能，会影响内容审核与版权，先不做）
- 编辑器内多语言并排显示
- 首发即支持 >2 种语言（结构已支持，加语言 = 加资源包）

#### i18n 验收标准

- 切换 `zh-CN ⇄ en` 后：编辑器 UI、积木面板与积木文字、菜单、错误提示、模板/素材名全部正确切换；
- 同一工程在两种语言下打开，内容与运行行为完全一致（`.gproj` 不含界面文案）。

## 附录 B：运行时执行流程（伪代码）

```ts
// 每帧（Phaser update）
function tick(dtMs: number) {
  input.poll();
  for (const thread of scheduler.threads) {
    let budget = 2000;
    while (thread.status === "running" && budget-- > 0) {
      const node = thread.next();
      switch (node.op) {
        case "wait": thread.sleep(node.seconds * 1000); break;
        case "repeat": thread.pushLoop(node); break;
        case "move": adapter.setTransform(...); break;
        // ...
        case "yieldFrame": thread.waitFrame(); break;
      }
      if (thread.yieldedThisFrame) break;
    }
  }
  adapter.render(dtMs);
}
```

## 附录 D：名词约定

- **积木**：用户拖拽的语法块（Blockly block）。
- **IR**：积木编译后的中间表示，运行时唯一执行对象。
- **runtime**：IR 解释器 + 调度器 + 适配层调用，浏览器内无框架依赖。
- **player**：把 runtime + 工程打在一起的可播放页面/包。
- **`.gproj`**：工程文件（zip：project.json + assets）。
- **local-first**：工程默认存本地，无需登录即可创作。
